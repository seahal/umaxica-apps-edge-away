# Accept-Language の解析コストを見直す

2026-11-18 調査（`a462a4f`）。対応は判断待ち。

クエリ付きの `GET /` では、Worker がレート制限のエラー画面に備えて
`Accept-Language` を解析する。制限を通過すると、ルートでも同じヘッダを解析する。
各回で候補をすべて分割・整列し、アプリ側では長さや件数の上限を設けていない。
`/about` でも言語選択を行い、このルートはトークン用レート制限の対象外となる。
[Worker 入口](../../src/cloudflare.ts)・[ルート](../../src/index.ts)・[言語選択](../../src/core/page.ts)

## 判断材料

拒否される要求でも CPU とメモリを使うこと、通過時に二重解析することはコードで確認した。
本番トラフィックでのコストや可用性への影響は未計測。
見直す場合は、エラー応答を返す時点での言語選択と、候補を全件整列せずに選ぶ方法を検討する。
比較時には、日本語・英語の優先順位、同順位の順序、既定の日本語、
429・503 応答の言語を既存の期待と照合する。[言語選択のテスト](../../test/page.test.ts)・[レート制限のテスト](../../test/rate-limit.test.ts)
