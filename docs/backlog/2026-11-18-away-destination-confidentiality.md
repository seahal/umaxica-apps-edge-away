# 発行元とログで遷移先 URL の機密性を確認する

2026-11-18 調査（`a462a4f`）。対応は判断待ち。

`GET /?at=…` の署名付き JWT には遷移先のパスとクエリが入る。
署名は改変を検知するが、内容は読める。発行元が個人情報や署名付きダウンロード URL を含めると、
Away JWT の期限が過ぎても履歴やコピー済みリンクにその値が残り得る。
Away は既知の認証用クエリ名などを拒否する。通常のパラメータ名やパスに入った機密値まで識別する仕組みはない。
[URL 検査](../../src/core/destination.ts)・[公開 URL に限定する発行契約](../../plans/2026-11-12-away-implementation-contract.md)

## 判断材料

- 発行元の Rails で署名前に何を検査しているかは未確認。個人情報、非公開リソースへの署名付きリンク、
  パスに秘密を含むリセットリンクを署名対象から除外できるか、発行側のコードとテストで判断する。
- Away のレスポンスには `no-store` と `no-referrer` があり、Workers のログ・トレースはクエリ除去を設定している。
  発行元、CDN、WAF、Logpush での記録内容は未確認。実際に利用する記録先に入口のクエリが残るかで、
  ログ設定の見直しが必要かを判断する。[レスポンスヘッダ](../../src/core/security_headers.ts)・[ログ設定](../../wrangler.jsonc)
